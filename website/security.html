Security

Last updated November 2, 2026

Financial and personal data deserve serious protection. This is how we protect it.

Encryption

  • At rest: the database is encrypted (SQLCipher), uploaded files with AES-256-GCM, and keys and API secrets are sealed and never stored in plain text.
  • In transit: every connection uses HTTPS with TLS 1.2 or higher, inside a private WireGuard network.
  • Backups are encrypted with a key kept off the server.

Network and access control

  • Servers have no public ports and are reachable only over a private network. New devices need approval.
  • Access is role-based and least-privilege, under a written access control policy.
  • Administrative access uses one central identity with multi-factor authentication, and you must sign in again every 12 hours.
  • Access is reviewed every quarter, with records kept. People leaving or changing role lose access through an automated process, and a daily job removes any server access that isn't approved.
  • Bank keys are held only by the core service; add-on components can never receive them.

Monitoring and patching

  • Security updates install daily. A weekly check covers vulnerabilities, key ages, network exposure, the firewall and access changes.
  • Every code change is scanned for vulnerable libraries and unsafe code before release.
  • Keys are rotated at least every 90 days.

AI safety

  • Sending, buying, booking and changing things need your yes, checked in code.
  • Emails, web pages and bank descriptions are treated as information, never as instructions.
  • Personal and financial data goes only to AI providers under terms that don't allow training on it. General tasks with no personal data may use other models.
